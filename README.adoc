== Sobre

A definir.

Este repositório mantém conteúdo em AsciiDoc. Ele funciona como componente Antora e também gera HTML, PDF e EPUB localmente.

== Criar uma Bíblia

=== 1. Atualize a identidade

Edite a tabela e a seção Sobre acima, `modules/ROOT/pages/index.adoc`, `antora.yml` e `antora-playbook.yml`.

Centralize os metadados das edições em `asciidoctor/publication.yml`:

[source,yaml]
----
author: A definir
isbn: ''

editions:
  main:
    title: Bíblia
    slug: biblia
    lang: pt-BR
----

`main` é o módulo neutro inicial. Para outras edições ou idiomas, crie um módulo com slug ASCII e uma entrada correspondente em `publication.yml`. Ao renomeá-lo, atualize também `antora.yml` e os `xref`. O campo `lang` seleciona o perfil em `asciidoctor/support/attributes/`.

=== 2. Substitua o conteúdo

Cada livro possui um diretório ordenado, um `index.adoc` e um arquivo por capítulo:

[source,text]
----
modules/main/pages/001-genesis/index.adoc
modules/main/pages/001-genesis/001-genesis-001.adoc
----

Use três dígitos, slugs ASCII e os mesmos caminhos nas edições correspondentes. O `nav.adoc` lista a edição e os livros, não todos os capítulos; cada índice de livro contém sua tabela de capítulos.

O modelo traz os 66 livros do cânon protestante, somente com o capítulo 1 e conteúdo genérico. Ajuste livros e ordem quando o cânon da publicação for diferente.

Registre a ordem linear em `asciidoctor/contents.adoc`:

[source,asciidoc]
----
\include::../modules/{edition-module}/pages/001-genesis/index.adoc[leveloffset=+1]
\include::../modules/{edition-module}/pages/001-genesis/001-genesis-001.adoc[leveloffset=+2]
----

A extensão `antora/extensions/bible-navigation.cjs` gera os seletores superiores durante o build sem modificar os arquivos de conteúdo. Preserve também `bible-sidebar.js`, que mantém o livro correspondente aberto no menu lateral.

=== 3. Substitua as capas

Mantenha estes nomes em `modules/ROOT/assets/images/`:

* `cover-complete.png`: capa pronta, usada no PDF e no EPUB;
* `cover-background.png`: fundo da página de título do PDF;
* `cover-banner.png`: imagem horizontal exibida no HTML.

=== 4. Preserve a infraestrutura

Não é necessário modificar `Rakefile`, `asciidoctor/support`, `antora/`, `Gemfile`, `package.json` ou os lockfiles ao trocar apenas a publicação.

== Executar localmente

=== Site Antora

Pré-requisitos: Git e Node.js 20 ou posterior.

[source,shell]
----
npm ci
npm start
----

O site é gerado em `build/site` e aberto no navegador.

=== HTML, PDF e EPUB

Pré-requisitos: Ruby 3.2 ou posterior e Bundler.

[source,shell]
----
bundle install
bundle exec rake
----

Os arquivos são gerados em `build/publications/<módulo>/`.

=== Validar antes de registrar mudanças

[source,shell]
----
npm exec -- antora antora-playbook.yml
bundle exec rake
----

Corrija referências ausentes e confirme os três formatos antes do commit.

== Publicar uma versão

O workflow `.github/workflows/release.yml` publica os arquivos de `build/publications` quando recebe uma tag anotada `vX.Y.Z`.

[source,shell]
----
git add --all
git commit -m "docs: revise publication content"
git push origin main

git tag -a v1.0.0 -m "Primeira publicação" -m "Inclui HTML, PDF e EPUB."
git push origin v1.0.0
----

Use uma nova versão para cada atualização publicada; não mova nem reutilize tags existentes.

== Usar em outro site Antora

Adicione este repositório às fontes do playbook agregador. O Antora importa `antora.yml` e `modules/`; a infraestrutura local não se torna conteúdo do site.

Para manter os seletores bíblicos, o agregador também precisa registrar uma extensão compatível com `page-bible-navigation`.
